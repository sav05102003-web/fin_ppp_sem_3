## Описание проекта

Telegram-бот подбирает рецепты по продуктам, составляет меню на неделю
и рассчитывает список покупок. Помогает учитывать пищевые предпочтения
и следить за временем приготовления с помощью сохраняемых таймеров.

| 🍲 Рецепты | 📅 Планирование | ✅ Проверки |
| :---: | :---: | :---: |
| 14 пошаговых рецептов | 7 дней × 3 приёма пищи | 37 автоматических тестов |

## Функциональные возможности

### Основной функционал

- Поиск рецептов по ингредиентам и просмотр пошаговых инструкций.
- Планирование завтраков, обедов и ужинов на семь дней.
- Список покупок с пересчётом количества на выбранные порции.
- Таймеры готовки с уведомлениями в Telegram.
- Выбор типа питания и исключение нежелательных ингредиентов.

### Дополнительный функционал

- Сохранение личных данных в SQLite и восстановление после перезапуска.
- Кнопки главного меню и подсказки команд.
- Демонстрация без токена и подключения к Telegram.
- Автоматические проверки логики и обработчиков.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/sav05102003-web/fin_ppp_sem_3.git
cd "fin_ppp_sem_3/cooking-assistant-bot(3.2)"
```

Все последующие команды выполняйте из папки `cooking-assistant-bot(3.2)`.

### 2. Создание виртуального окружения

В соответствии с техническими требованиями каталог `venv/` включён в Git
и не добавлен в `.gitignore`. Сохранён каркас настоящего окружения Windows:
конфигурация, интерпретаторы и скрипты активации. Установленные пакеты
`site-packages/` не версионируются; для них есть файлы зависимостей.
Окружение связано с местом установки Python, поэтому после клонирования
обязательно пересоздайте его на своём компьютере. `--clear` очищает
только каталог `venv`.

**Windows PowerShell:**

```powershell
python -m venv --clear venv
.\venv\Scripts\Activate.ps1
```

Если PowerShell запрещает активацию, используйте интерпретатор напрямую:
`venv\Scripts\python.exe`. Изменять политику выполнения скриптов не требуется.

**Windows cmd:**

```bat
python -m venv --clear venv
venv\Scripts\activate.bat
```

**macOS/Linux:**

```bash
python3 -m venv --clear venv
source venv/bin/activate
```

В Debian/Ubuntu при отсутствии модуля `venv` установите системный пакет
`python3-venv`. На macOS/Linux допустимо использовать `python3` вместо `python`.

### 3. Установка зависимостей

В активированном окружении:

```bash
python -m pip install -r requirements.txt
```

Без активации на Windows:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Без активации на macOS/Linux:

```bash
./venv/bin/python -m pip install -r requirements.txt
```

`requirements.txt` подключает ограничения из `requirements-lock.txt`,
поэтому устанавливаются проверенные версии всех зависимостей. Сохранённый
учебный каркас создавался с `--without-pip`; пересоздание из шага 2
добавляет pip. На машине разработки библиотеки установлены в этот `venv`
через внешний pip с параметром `--python`.

### 4. Получение и настройка токена

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте название и уникальное имя, заканчивающееся
   на `bot`. Сохраните полученный токен.
3. Скопируйте `.env.example` в `.env`.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

macOS/Linux:

```bash
cp .env.example .env
```

Вставьте токен в файл:

```dotenv
BOT_TOKEN=вставьте_токен_от_BotFather
BOT_DB_PATH=data/users.sqlite3
```

Это пример значения, а не рабочий токен. В `config.py` секретов нет.
Можно задать `BOT_TOKEN` и `BOT_DB_PATH` переменными окружения: они имеют
приоритет над `.env`. Относительный путь базы считается от папки проекта.
Сам файл `.env`, базы SQLite и журналы исключены из Git. При утечке токена
перевыпустите его у BotFather.

### 5. Запуск программы

```bash
python main.py
```

На Windows без активации: `.\venv\Scripts\python.exe main.py`.
Откройте своего бота в Telegram и отправьте `/start`. Бот работает
в режиме long polling; остановка — `Ctrl+C`. Держите запущенным только
один экземпляр с одним токеном и одной базой. Вебхук для этого бота
должен быть отключён.

При отсутствии токена программа выводит подсказку и завершается с кодом 1.
Для локальной проверки доступны отдельные режимы:

```bash
python main.py --check
python main.py --demo
```

`--check` проверяет каталог и создание SQLite. `--demo` выполняет сценарий
поиска, планирования, покупок и таймеров во временной базе, затем удаляет её.
Оба режима работают без токена, не обращаются к Telegram и не изменяют
личную базу бота. Текст демонстрации сохранён в
[docs/demo.txt](docs/demo.txt).

## Управление и команды

В личном чате доступны кнопки «Рецепты», «Меню», «Покупки», «Таймеры»,
«Питание» и «Помощь». Любой текст без `/` считается списком ингредиентов.
Бот работает с личными чатами: в группе предложит перейти в личный чат.

| Команда | Пример и результат |
| --- | --- |
| `/start`, `/help` | Главное меню и полная справка |
| `/find продукты` | `/find рис, морковь, перец` — до 7 рецептов с совпадениями |
| `/find` | Повторить поиск с последним набором продуктов |
| `/recipe ID` | `/recipe 3` — состав, базовые порции и шаги |
| `/diet` | Посмотреть доступные типы питания |
| `/diet тип` | `/diet веганское` — сохранить предпочтение |
| `/exclude продукты` | `/exclude молоко, яйцо` — заменить список исключений |
| `/exclude нет` | Очистить исключения |
| `/profile` | Посмотреть тип питания, исключения и продукты |
| `/tips` | Рекомендации и примеры подходящих блюд |
| `/plan авто N` | `/plan авто 2` — заменить меню недели, по 2 порции |
| `/plan день приём ID N` | `/plan пн ужин 3 2` — заменить отдельный приём пищи |
| `/menu` | Показать меню текущей календарной недели |
| `/clear_menu` | Удалить меню текущей недели и отметки покупок |
| `/shopping` | Количества всех продуктов для меню, кроме воды |
| `/buy N` | `/buy 1` — переключить отметку покупки из текущего списка |
| `/timer время название` | `/timer 5 паста` — уведомить через 5 минут |
| `/timers` | Показать свои активные таймеры |
| `/cancel_timer ID` | `/cancel_timer 1` — отменить свой таймер |

Порции — целое число от 1 до 12, по умолчанию 2. Дни: `пн`, `вт`, `ср`,
`чт`, `пт`, `сб`, `вс`; приёмы пищи: `завтрак`, `обед`, `ужин`.
Планируется текущая неделя с понедельника по воскресенье, часовой пояс
Москва, UTC+3. Прошедшие дни недели тоже остаются в плане.
При наступлении новой недели отображается новое меню; старое хранится в базе.

Время таймера: число без суффикса означает минуты; `10с` — секунды,
`2м` — минуты, `1ч` — часы; допускается десятичная точка или запятая.
Диапазон — от 1 секунды до 24 часов, до 10 активных таймеров на человека.

## Как работают функции

### Подбор рецептов

Названия переводятся в нижний регистр, `ё` заменяется на `е`, повторные
пробелы убираются. Поддерживаются заданные синонимы, например
`помидоры` → `помидор`, `курица` → `куриное филе`, `макароны` → `паста`.
Продукты вводятся через запятую или `;`, до 30 наименований. Полного
морфологического анализа нет: используйте названия из карточек рецептов.

Сначала отбираются блюда с хотя бы одним совпавшим продуктом, затем
применяются предпочтения и исключения. Результат сортируется по доле
недостающих ингредиентов, их количеству и ID. Вода не учитывается при
поиске и в покупках. Это локальный каталог из 14 рецептов, внешний API не нужен.
Карточка по прямому ID доступна всегда, но при несовместимости с профилем
показывается предупреждение. В меню неподходящий рецепт добавить нельзя.

### Меню и покупки

Автоплан составляет 7 дней по 3 приёма пищи, выбирает блюда с подходящей
меткой приёма пищи, старается избегать повторений в течение дня и уменьшать
их за неделю. Небольшой каталог допускает повторы. Если подходящего завтрака,
обеда или ужина нет, старое меню сохраняется и возвращается пояснение.
Планирование не является расчётом суточного рациона или калорийности.

Для каждой записи меню количество рассчитывается как
`количество_в_рецепте × выбранные_порции / базовые_порции`.
Одинаковые продукты с одинаковой единицей складываются. Список отражает
весь объём на неделю: найденные дома продукты автоматически не вычитаются,
поскольку их количество пользователь не вводит. Соль и специи по вкусу
не включены. При изменении меню отметки покупок сбрасываются.
Смена `/diet` или `/exclude` очищает сохранённые меню и отметки пользователя;
снова выполните `/plan авто` или заполните меню вручную.

### Таймеры и сохранение данных

Таймер записывается в SQLite до подтверждения пользователю. JobQueue
проверяет готовые записи раз в секунду; просроченные таймеры после запуска
тоже отправляются. Уведомление помечается отправленным после успешного
ответа Telegram. При временной ошибке выполняется до пяти попыток с
интервалом не менее 30 секунд; при ограничении Telegram учитывается
`RetryAfter`. Если бот заблокирован или Telegram отклонил запрос,
таймер получает статус `failed`. Эти статусы доступны в таблице `timers`.

При выключенной программе уведомления не отправляются. Возможны задержки
сети; после сбоя между отправкой и записью результата уведомление может
повториться. Для уведомлений не требуется повторное создание таймера
после перезапуска. Одновременный запуск нескольких экземпляров с одной
базой не поддерживается.

Профили, меню, отметки и таймеры привязаны к ID пользователя.
Доступ к ним осуществляется в личном чате. База хранится локально
без шифрования; для резервного копирования остановите бота и скопируйте
`data/users.sqlite3`. Тексты сообщений и токен не выводятся в журнал.

### Пищевые предпочтения

Доступны обычное, вегетарианское, веганское, безглютеновое и безмолочное
питание. Команда `/tips` объясняет выбранный вариант и предлагает блюда
каталога. Метки относятся к составу рецепта, а не к медицинским показаниям.
Исключение продукта проверяется по его каноническому названию, например
`/exclude яйцо` не допускает рецепты с ингредиентом `яйцо`. Оно не раскрывает
состав покупных продуктов: при аллергии проверяйте этикетки и возможные следы.

## История разработки

Работа добавлена в существующий репозиторий отдельной папкой.
Первый коммит, относящийся к этой работе, содержит только README
и имеет сообщение `Стрельцов Андрей`. Последующие этапы:

1. Структура, виртуальное окружение и каталог рецептов.
2. SQLite, предпочтения, недельное меню, покупки и таймеры.
3. Команды Telegram, уведомления и локальная демонстрация.
4. Тесты, результаты проверки и полная документация.
5. Запуск настоящего Telegram-бота, ссылка для пользователей и оформление README.

Предыдущие проекты репозитория сохранены. Соответствие пунктам задания
приведено в [docs/requirements-checklist.md](docs/requirements-checklist.md).
